# Serbia geographic coverage dataset — sources and verification

**Issue:** FUZZ-6 · **Date:** 2026-08-19 · **Artifact:** `data/serbia-geo.json`,
regenerated by `scripts/build-serbia-geo.py`

## What the dataset contains

162 records: the **145 Serbian local self-government units** (117 municipalities

- 27 cities + the City of Belgrade) plus the **17 city municipalities of
  Belgrade**, which carry `type: "city_municipality"` and `parent_id: "beograd"`.

Kosovo and Metohija's 28 municipalities are deliberately excluded — not
administered by Serbian institutions, out of scope for this project.

## Where each field comes from

| Field                                                    | Source                                                                                                                                                 |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| unit list                                                | RZS 2022 census table, transcribed at [sr.wikipedia: Градови и општине Србије](https://sr.wikipedia.org/wiki/Градови_и_општине_Србије)                 |
| `population`, `area_km2`, `settlement_count`, `district` | same table — [RZS 2022 census, G20234001](https://publikacije.stat.gov.rs/G2023/Pdf/G20234001.pdf)                                                     |
| `landline_prefix`, `landline_group_center`               | RATEL numbering plan, transcribed at [en.wikipedia: Telephone numbers in Serbia](https://en.wikipedia.org/wiki/Telephone_numbers_in_Serbia)            |
| `postal_codes`                                           | Pošta Srbije list, transcribed at [sr.wikipedia: Списак поштанских бројева у Србији](https://sr.wikipedia.org/wiki/Списак_поштанских_бројева_у_Србији) |
| `search_variants`                                        | generated from rules + a hand-written override table, reviewed entry by entry                                                                          |

## Verification

**The unit list is cross-checked at build time.** `scripts/build-serbia-geo.py`
independently parses [en.wikipedia: Municipalities and cities of
Serbia](https://en.wikipedia.org/wiki/Municipalities_and_cities_of_Serbia) —
which is sourced from the Law on Territorial Organisation of the Republic of
Serbia (Sl. glasnik RS 129/2007, 18/2016, 47/2018) — and aborts if the two lists
disagree by even one name. They currently agree on all 145 units.

Independent checks that came out right, and are asserted in `src/lib/geo.test.ts`:

- **Region totals.** Vojvodina 45, Šumadija and Western Serbia 52, Southern and
  Eastern Serbia 47, Belgrade 1. That is the official NSTJ-2 breakdown, and it
  falls out of the parsed district assignments without any manual correction.
- **Network groups.** 27 RATEL area codes, each with exactly one group centre.
- **`name_ascii`** equals `foldDiacritics(name_sr)` from `src/lib/text/fold.ts`
  for all 162 records, so the dataset cannot drift from the project's folding.

Two parsing traps that would have corrupted the data silently:

1. The sr.wikipedia table splits cities that have city municipalities (Niš,
   Vranje, Užice, Požarevac) across `rowspan` blocks with an `Укупно` total row.
   A naive row parser reads `Медијана` (83,113) as if it were Niš and never sees
   Niš (249,501) at all. The build reads the total row.
2. The postal list files some seats under a different post-office name
   (`Rača Kragujevačka` for Rača, `Petrovac` for Petrovac na Mlavi) and gives
   some cities the main-post-office code (`32101` for Čačak) rather than the
   round code in general use. Those eight are pinned explicitly.

## The part that actually matters: `search_variants`

Serbian is inflected. A listing reads _"fasader u **Novom Sadu**"_ or
_"stovarište iz **Kragujevca**"_ — never _"fasader Novi Sad"_. Searching the
nominative alone loses most of the corpus.

Each record carries the **nominative, locative and genitive**, each in its
diacritic and ASCII-folded spelling, plus the same three forms in Cyrillic
(`search_variants_cyrillic`) — Serbian directories publish both scripts.

The generator applies four rules and an override table:

- `-ac` → fleeting _a_ drops: `Kragujevac` → `Kragujevca` / `Kragujevcu`
- `-a` feminine: `Subotica` → `Subotice` / `Subotici`
- `-o` / `-e` neuter: `Valjevo` → `Valjeva` / `Valjevu`
- otherwise masculine consonant stem: `Bor` → `Bora` / `Boru`

43 names are overridden because a rule would get them wrong:

- **Multi-word** — both words decline: `Novi Sad` → `Novom Sadu`,
  `Bačka Palanka` → `Bačkoj Palanci`, `Sremska Mitrovica` → `Sremskoj Mitrovici`.
- **Plurale tantum** — `Odžaci` → `Odžacima`, `Sremski Karlovci` →
  `Sremskim Karlovcima`, `Lučani`, `Pećinci`, `Vladimirci`, `Žabari`.
- **Consonant alternation** — `Šabac` → `Ša**p**cu`, `Golubac` → `Golu**p**cu`.
- **Fleeting _a_ outside `-ac`** — `Žabalj` → `Žablju`, `Krupanj` → `Krupnju`,
  `Ražanj` → `Ražnju`, `Sečanj` → `Sečnju`, `Čačak` → `Čačku`.
- **Adjectival feminine** — `Grocka` → `Grockoj`, not `Grocki`.
- **i-stem feminine** — `Nova Varoš` → `Nove Varoši` in both cases.

All 162 generated variant sets were read through by hand against the rules
above; the override table is the list of what that review caught.

## Known limits

- **Landline codes are not unique.** One code covers a whole RATEL network group
  — `011` spans Belgrade and 17 city municipalities, `012` spans eight
  Braničevo municipalities. Phone-only city inference must use
  `landlineGroupCenter()` and treat the answer as a best guess, not a fact.
- **`postal_codes` is the seat's code only**, not every code inside the unit.
- Four Belgrade city municipalities (Zemun, Mladenovac, Obrenovac, Surčin) carry
  2011 populations — no 2022 figure was published in the sources used. Flagged
  per record in `population_census_year`. Belgrade's own figure is 2022.
- **Niš, Vranje, Užice and Požarevac also have city municipalities** (Medijana,
  Niška Banja, Vranjska Banja, Sevojno, Kostolac, …) which are _not_ carried as
  separate records. Searching the parent city covers them. If a later crawl
  finds that ads geo-tag by `Niška Banja` rather than `Niš`, adding those eleven
  records is a one-line change to the build script.

## Priority tiers

Computed over the 145 units by 2022 population: **tier 1** = the 20 most
populous, **tier 2** = population ≥ 20,000, **tier 3** = the rest. Belgrade's
city municipalities are tiered separately — the 10 urban-core ones are tier 1,
the 7 suburban ones tier 2.

Result: **30 tier 1**, **58 tier 2**, **74 tier 3**.

`municipalitiesByPriority()` sorts tier ascending, population descending, so a
crawl that is cut short after _N_ municipalities has still covered the _N_ with
the most businesses in them.
